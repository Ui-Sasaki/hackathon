# 音声入力（依頼作成）の方針

要件定義書 3.3「音声入力（優先度P1）」、F-01、11.3、12 に対応する。
実装は `tetote/src/voice/` と `tetote/src/app/help/request-voice.tsx` にある。

## 1. 画面の流れ

| 状態 | 画面 | 利用者が行える操作 |
|---|---|---|
| `idle` | マイクの利用目的と音声の扱いを表示 | 録音を始める／手で入力へ切り替える |
| `listening` | 録音中であることを表示 | 録音を止める／録音を取り消す |
| `transcribing` | 文字起こし中であることを表示 | なし |
| `review` | 文字起こし結果を編集できる形で表示 | 文字を直す／確認へ進む／録音し直す／取り消す |
| `confirmed` | 確認画面へ遷移 | — |
| `error` | 失敗理由と次の操作を表示 | もう一度録音する／手で入力へ切り替える |

状態遷移は `tetote/src/voice/session.ts` の `voiceReducer` に閉じており、画面から切り離してテストする。

## 2. 利用者の確認を挟む位置

- 文字起こし結果は `review` 状態で編集可能なテキストとして表示し、この時点では送信しない。
- 送信テキストは `confirm` 操作を受けた後にだけ生成され、`confirmed` 状態からしか取り出せない。
- したがって利用者の確認なしに構造化（AI処理）も公開も行わない。F-01「9. ユーザーの確認後に公開する」に対応する。

## 3. 個人情報のマスキング

`tetote/src/voice/masking.ts` が、確認後のテキストへ送信直前にマスクを適用する。

| 種別 | 例 | 置き換え後 |
|---|---|---|
| メールアドレス | `taro@example.com` | `[メールアドレス]` |
| 電話番号 | `090-1234-5678` / `09012345678` | `[電話番号]` |
| 詳細住所 | `7丁目1番地` / `921-8501` / `3-1-2` | `[住所]` |
| 証明書番号 | `学籍番号は A1234567` | `[証明書番号]` |

- 音声認識結果に混ざる全角数字は、検出前に半角へ正規化する。
- 何を伏せたかは `review` 画面に表示し、利用者が送信前に把握できるようにする。
- 氏名は正規表現で確実に判別できないため、この層ではマスクしない。氏名の扱いはサーバー側の構造化処理（Issue #32）で行う。

## 4. 音声データの扱い

- 音声はブラウザとOSの音声認識機能が処理し、このアプリは音声ファイルを**保存も送信もしない**。保持期間は録音中のみである。
- アプリが保持するのは文字起こし結果の文字列だけで、画面のメモリ上にのみ置く。サーバーやストレージへは保存しない。
- 破棄のタイミングは次の3つ。
  1. 「取り消す」を押したとき（`cancel`）
  2. 画面を離れたとき（`useEffect` のクリーンアップで `abort()` を呼ぶ）
  3. 確認して次の画面へ渡した後（画面の状態ごと破棄される）
- 「録音を取り消す」と画面離脱では、認識を `abort()` で止めるため文字起こし結果を受け取らない。
- 要件定義書 12「個人情報をURL、エラーメッセージ、分析ログへ含めない」に対応するため、確認画面へ渡すのはマスク済みテキストだけとする。画面間の受け渡しを完全にURL経由でなくす対応は、API接続（Issue #57）で行う。

## 5. 対象ブラウザでの動作方針

音声認識には Web Speech API（`SpeechRecognition` / `webkitSpeechRecognition`）を使う。

| ブラウザ | 音声入力 | 方針 |
|---|---|---|
| Chrome（デスクトップ・Android） | 利用可 | 主な対象。`ja-JP` で単発認識する |
| Edge（デスクトップ） | 利用可 | Chromeと同じ扱い |
| Safari（macOS・iOS） | `webkitSpeechRecognition` で利用可 | 実装差があるため、失敗時は必ず手入力へ誘導する |
| Firefox | 利用不可 | 非対応として案内し、手入力のみを提示する |
| 上記以外 | 不明 | 非対応として扱う |

- 対応判定は `webSpeechAdapter.isSupported()` が行い、非対応なら画面表示時点で `unsupported` として案内する。
- 非対応ブラウザでは録音ボタンを出さず、「手で入力へ切り替える」だけを提示する。
- 対応ブラウザでも、音声入力は必須ではない。すべての状態から手入力へ切り替えられる。

## 6. 失敗時の案内

ブラウザごとに異なるエラーコードは `toErrorReason()` で次の4種類へ寄せる。

| エラーコード | 扱い | 案内 |
|---|---|---|
| `not-allowed`, `service-not-allowed` | `permission-denied` | 設定で許可するか、手入力へ切り替える |
| `audio-capture` | `recording-failed` | マイクの状態を確認して録音し直す |
| `no-speech` | `empty-transcript` | 録音し直すか、手入力へ切り替える |
| その他（`network` など） | `transcription-failed` | 録音し直すか、手入力へ切り替える |
| `aborted` | 失敗として扱わない | 利用者が取り消した場合に発生するため無視する |

失敗しても、それまでに得ていた文字は `fallbackTextOf()` で手入力へ引き継げる形で保持する。

## 7. テスト

`tetote/` で `npm test` を実行する。

| ファイル | 対象 |
|---|---|
| `tetote/src/voice/masking.test.ts` | 個人情報マスク（要件定義書 15.1「個人情報マスク」） |
| `tetote/src/voice/session.test.ts` | 権限拒否、取消、再録音、文字修正、送信の状態遷移 |
| `tetote/src/voice/recognition.test.ts` | ブラウザAPIのエラーコード変換と取消時の挙動 |
