# 地域コードの扱い

## 現状（2026-09-04 の応急処置）

地域は独自の3区分で管理している。

| areaCode | 表示名 | 中心座標（GPS変換用） |
|---|---|---|
| `AREA-001` | 大学周辺 | 43.062, 141.354 |
| `AREA-002` | 大学北側 | 43.082, 141.350 |
| `AREA-003` | 駅周辺 | 43.068, 141.351 |

### 応急処置で変えたこと

本番で「依頼一覧が地域エラーで表示されない」「GPSを許可しないと依頼を出せない」問題への最小の修正。

- 地域が決まらないとき（`areaCode` 未指定、登録地域なし、GPS失敗）は 422 で止めず、
  既定地域 `AREA-001` を使う。`POST /locations/resolve` と依頼一覧の `origin` は
  `source: "default_region"`、`fallbackUsed: true` でそれが分かる。
- `POST /requests` の `areaCode` は省略できる。省略時は登録地域、無ければ既定地域。
- 指定された `areaCode` が未知の値のときは従来どおり `422 REGION_SELECTION_REQUIRED`。
- 確認画面の「公開する」は、地域が取れていなくても押せる（`areaCode` を送らない）。

原因: オンボーディングは都道府県名（`region`）しか保存せず、`areaCode` を設定しないため、
登録地域が無い利用者が大半だった。一覧画面の地域ボタンにも処理が無い。

## 次にやること（市区町村単位への切り替え、発表後）

チーム合意済みの方針（2026-09-04）:

- 地域識別子は **全国地方公共団体コード（JIS X 0401/0402、5桁・検査数字なし）**。
  政令指定都市は行政区単位（例: `01102` 北海道札幌市北区）。
- 市区町村マスタは国土地理院 地理院地図の `https://maps.gsi.go.jp/js/muni.js` から生成する。
  生成スクリプトと JSON は作業ブランチ（`wip-municipality-regions` stash）にある。
  取得元・取得日をJSONに記録し、再生成で更新する。廃止・統合された自治体は
  地理院地図の一覧から消えるため、旧コードが残るデータは再生成時の差分で検出し
  corrective migration で移す。
- GPS は国土地理院 逆ジオコーダ API
  （`https://mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress?lat=..&lon=..`、
  無料・キー不要、`muniCd` が上と同じ5桁コード）で市区町村へ変換し、座標は破棄する。
- 旧コードの変換先（中心座標を逆ジオコーダで変換した結果、合意済み）:

| 旧 | 新 | 表示名 |
|---|---|---|
| `AREA-001` | `01101` | 北海道札幌市中央区 |
| `AREA-002` | `01102` | 北海道札幌市北区 |
| `AREA-003` | `01101` | 北海道札幌市中央区 |

- DB は forward-only migration で `operational_areas` に市区町村を追加し、
  `users.area_code` / `requests.area_code` を上の表で更新してから旧行を削除する。
  適用前に件数を読み取り専用SQLで確認する。適用はSupabase担当が行う。
